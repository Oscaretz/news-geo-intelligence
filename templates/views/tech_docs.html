Flask (Web): Proporciona endpoints RESTful asíncronos y sirve la interfaz frontend construida con Tailwind CSS y Vanilla JS.

2. Motor de Scraping y Extracción

El sistema implementa una capa de extracción web altamente concurrente y resistente a bloqueos automatizados, encargada de la recolección del texto completo y metadatos de las noticias.

Descubrimiento Inicial (Google News RSS): La fase inicial de descubrimiento explota los feeds RSS de Google News para obtener metadatos estructurados, URLs base y deduplicación inicial antes de proceder al web scraping profundo del artículo original.
Evasión de Bloqueos (curl_cffi / Playwright): Se emplea curl_cffi para suplantar firmas TLS y huellas de navegadores, esquivando protecciones anti-bot de forma ligera. Para sitios con renderizado dinámico intenso, se orquesta un headless browser con Playwright.
Parseo y Limpieza (Trafilatura & BeautifulSoup): La extracción algorítmica principal es manejada por Trafilatura para discernir de forma heurística el cuerpo del artículo descartando boilerplate. BeautifulSoup actúa como motor de respaldo y para la obtención de metadatos estructurales como og:image.
Concurrencia Asíncrona (ThreadPoolExecutor): Dado que las operaciones son intensivas en I/O de red, se implementa multiplexión mediante ThreadPoolExecutor y corrutinas asíncronas, permitiendo el scrapeo simultáneo de múltiples URLs sin bloquear el Event Loop principal de Flask.

3. Pipeline ETL y Orquestación (Dagster)

La lógica de negocio asíncrona está encapsulada en Software-Defined Assets (SDAs) de Dagster (etl/definitions.py). Este orquestador coordina las recolecciones de información y los motores de inferencia masiva.

El flujo inicia extrayendo metadatos no procesados, los cuales se agrupan y paralelizan hacia los nodos computacionales (LLM). Si ocurre una falla irrecuperable en un lote, el sistema descarta los registros en una Dead Letter Queue (DLQ) local para inspección manual, permitiendo que el pipeline principal continúe sin afectar la integridad del DAG.

Tablas de Dimensión: dim_date, dim_source, dim_entities.

La ingesta utiliza lógica idempotente mediante operaciones UPSERT (ON CONFLICT DO UPDATE o DO NOTHING), garantizando que las reejecuciones del ETL no generen duplicados ni violaciones de primary keys.

Streaming API: Implementado vía Server-Sent Events (SSE) nativos en Flask para el renderizado asíncrono y progresivo de las respuestas en el frontend, evitando timeouts HTTP.
Inyección de Contexto: El LLM recibe dinámicamente un volcado serializado de métricas y acceso a las ejecuciones históricas para responder utilizando la técnica Retrieval-Augmented Generation.

7. Capa de Catálogos (GeoJSON & i18n)

El sistema expone configuraciones modulares permitiendo escalar la plataforma horizontalmente sin modificar el código base.

imageDiagrama / Captura
Caché en Memoria (Geometrías): Las topologías territoriales se precargan (geojson_cache.py) desde map_config.json y archivos vectoriales estáticos, reduciendo dramáticamente el consumo de I/O en la renderización de Leaflet.
Internacionalización (i18n): El frontend abstrae un diccionario inyectado que permite conmutar claves estáticas data-i18n en el DOM, así como traducciones dinámicas programáticas a través del método i18n.t(). Además, cuenta con un motor de traducción mediante expresiones regulares (translateStep) para localizar en tiempo real los mensajes emitidos por los jobs de backend asíncronos.

8. Despliegue y Repositorio

El despliegue está contenerizado. Los comandos operativos principales son los siguientes:

# 1. Clone the repository
git clone https://github.com/Oscaretz/news-geo-intelligence
cd news-geo-intelligence

# 2. Configure environment variables
cp .env.template .env
# Edit .env (DATABASE_URL and API Keys: GROQ, GEMINI)

# 3. Build and launch services
docker-compose up -d --build
